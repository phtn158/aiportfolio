n8n workflow design — Med Spa vertical · Google Sheets as the data store · built from the AIaaS_Small_Business_Client_Outreach_Plan

What n8n actually is

n8n is a visual workflow builder: you drag nodes onto a canvas and connect them with lines to define what happens, step by step, when something triggers the workflow. Each node does one job — call an API, filter data, ask an AI model a question, write a row to a spreadsheet — and passes its output to the next node as structured data (JSON). You're not writing a program from scratch; you're wiring pre-built blocks together, and dropping into a bit of JavaScript only inside individual nodes when you need custom logic.

ConceptWhat it means
Trigger nodeThe node that starts a workflow — a schedule ("every day at 9am"), a webhook (an external system pings a URL), or manual click.
Action nodeDoes something with data: HTTP Request (call an API), Google Sheets (read/write rows), Gmail, Slack, etc. n8n has 400+ built-in integrations.
AI nodeSends data to Claude/OpenAI/etc. with a prompt and gets structured output back — this is how scoring and drafting get done.
IF / Switch nodeBranches the workflow based on a condition, e.g. "if score ≥ 7, continue; else stop."
Expression {{ }}Lets you reference data from a previous node inside any field, e.g. {{$json.business_name}}.
ExecutionOne full run of a workflow, logged so you can see exactly what data flowed through each node — this is your debugging tool.
CredentialA saved, encrypted connection to an external account (your Google Sheet, your Claude API key, your Gmail) that any node can reuse.
You can run n8n two ways: n8n Cloud (hosted, ~$20–50/mo, zero setup) or self-hosted (free, runs on a $5–10/mo VPS or even your own machine, slightly more setup). For a first build I'd start on Cloud so we're not debugging server config on top of learning the tool.

Workflow by workflow

1 · Prospect Sourcing

Trigger Runs weekly on a schedule.
  • Google Places / Maps API node — searches "med spa" against your target city list, returns name, address, phone, website, rating, review count.
  • Google Sheets node — appends new rows to the Prospects tab; a lookup step checks business name against existing rows first so nothing gets duplicated.

Output written to Sheet: Business name, Website, Phone, Industry, Google rating/reviews, Outreach status = "New"

2 · Enrichment

Trigger Fires when a row's status is "New."
  • HTTP Request nodes pull the website HTML and the Instagram profile/recent posts.
  • Claude node reads that raw content and extracts: decision-maker name (from About/Team pages), whether an online booking system exists, and signs of customer inquiry patterns (comments asking about pricing/availability/booking).

Output: Decision maker, Instagram/social profile, Online booking system, Customer inquiry patterns, Number of locations — status → "Enriched"

3 · AI Scoring

Trigger Fires on status = "Enriched."
  • Claude node is given the doc's exact 5-criterion rubric (active social presence, inquiry volume, booking workflow, visible service pain, locations/ability to pay — 0–2 each) and returns a score plus a one-line rationale.
  • IF node branches: score ≥ 7 → "Ready for Outreach"; below → "Low Priority / Nurture."

Output: Prospect score, Potential AI opportunity (free text), Outreach status

4 · Outreach Drafting

Trigger Fires on status = "Ready for Outreach."
  • Claude node drafts the Day 1 email and Day 4 follow-up, prompted with the doc's positioning ("we help med spas automatically respond to Instagram and website inquiries...") plus the specific opportunity found in research — so every email references something real about that business, not a generic template.

Output: Email draft (Day 1), follow-up draft (Day 4) saved to the Sheet — status → "Drafted." Nothing sends automatically yet; you review drafts before the sequence workflow picks them up (recommend keeping a human-approval step here at first).

5 · 14-Day Sequence Runner

Trigger Runs daily.
  • Reads every "Drafted"/"In Sequence" row, checks how many days since first contact, and fires the matching touch: Day 1 email (Gmail node), Day 2 IG/LinkedIn (queued for manual send — these channels don't have safe APIs for outbound automation), Day 4 follow-up, Day 7 demo, Day 10 ROI message, Day 14 close-the-loop.
  • Updates Last Contact / Next Follow-up on every run; auto-moves non-responders to "Nurture" after Day 14.

6 · Metrics Rollup

Trigger Runs weekly.
  • Counts rows by status to compute response rate, meeting rate, demo rate, proposal rate, close rate, and (once you enter spend) CAC — written to a Metrics tab matching the doc's table exactly.

Build order I'd suggest

  • Phase 1: Google Sheet template (all tabs/fields) + Workflow 1 (Sourcing) + Workflow 3 (Scoring) — get a clean, scored prospect list before automating any outreach.
  • Phase 2: Workflow 2 (Enrichment) layered in once sourcing/scoring is validated on a real batch.
  • Phase 3: Workflow 4 (Drafting) with a human-approval step — you read every draft before it can send, at least for the first few weeks.
  • Phase 4: Workflow 5 (Sequence runner) once you trust the drafts, then Workflow 6 (Metrics) to close the loop.
Two things worth flagging early: Instagram and LinkedIn don't have safe, ToS-compliant APIs for automated outbound messaging — those touches stay a manual "queue" a human executes from a daily task list the workflow generates, rather than a bot that DMs on your behalf. And email sending at volume needs a warmed-up domain/inbox (via Gmail API, or a tool like Instantly) to avoid spam flags — worth setting up before Workflow 5 goes live.
